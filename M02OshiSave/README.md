# M02OshiSave — 好きなものを追加して保存する

Monacaのコマ5〜7で作る「好きなものノート」の完成見本です。日常の中で見つけた好きなものを追加し、一覧と詳細で読み返します。初期の題材は好きな音楽、カレー、公園です。

## 画面の構成

| 画面 | できること |
| --- | --- |
| 一覧 | 保存した内容を表示し、詳細や追加画面へ進む。保存状態を確認し、初期の内容へ戻す |
| 追加 | 名前・種類・好きな理由を入力して保存する。空入力・保存失敗の案内を読む |
| 詳細 | 選んだ名前・種類・理由を読み、一覧へ戻る |

## 使用しているAPI

- Onsen UI 2.12.9：`ons-navigator`、`ons-page`、ツールバー、戻るボタン、一覧、ボタン。画面遷移には`pushPage`・`popPage`、値の受け渡しには`data`を使います。
- `localStorage.getItem` / `setItem` / `removeItem`：同じオリジンのブラウザ保存。JavaのSharedPreferences、SwiftのUserDefaultsとの違いを比較STEPで説明します。
- `JSON.stringify` / `JSON.parse`：配列と文字列の変換。この単元の新概念です。
- `try` / `catch`、`Array.isArray`、`typeof`：読み取り・保存失敗と、復元した値の構造を確認します。Java／Swiftの例外処理・型確認と比較します。
- 入力は標準HTMLの`input`・`textarea`です。Web基礎と同じ`value`・`trim`・イベント処理で読みます。データは`textContent`に設定します。

## 処理の流れ

1. 一覧ページの`init`で、保存キー`jec-25cm-oshi-save-v1`を読みます。値がなければ初期データを表示します。
2. 値があればJSONを配列へ復元し、各項目が名前・種類・コメントの文字列を持つか確認します。読めない場合は元の保存内容を残し、追加を止めて画面に知らせます。
3. 入力は前後の空白を取り除き、3欄とも必要とします。表示中の配列のコピーへ追加し、保存に成功してから一覧を更新します。失敗した場合は入力画面と元の配列を残します。
4. 一覧から詳細へ項目を渡し、戻ったときは一覧の状態を保ちます。
5. 初期化は確認欄で実行・中止を選びます。`removeItem`でこのアプリのキーだけを削除し、成功してから初期の内容を表示します。

## 実装のポイント

- 通常版の公式`MonacaMinimumTemplate`（blank 4.0.0、Cordova12）を複製し、M01の一覧・詳細と題材を引き継いでいます。原本のライセンスと標準素材を保持し、テキストの改行をLFへそろえています。
- 新概念はJSONです。保存API、配列のコピー、例外処理・型確認、入力や画面遷移は既知技術との比較で説明します。教材には開始時のコードと必要な比較を再掲し、M01の教科書へ戻る前提にはしません。
- 画面に表示する名前や理由をHTMLの文字列へ混ぜません。`<`なども文字として表示します。
- 連続クリックでページを重ねない真偽値と現在ページの確認を残し、追加保存が成功した後のボタンも無効化して重複追加を防ぎます。
- 保存内容を読めなかった場合、自動的に初期データで上書きしません。初期化の確認後だけ、このアプリの保存内容を削除します。他のアプリの保存領域を消す`localStorage.clear()`は使いません。

## 保存と公開URLの違い

保存は同じブラウザ・同じオリジン内のものです。MonacaのプレビューURL、ブラウザ、端末が変わった場合は別の保存領域になります。プライベートブラウズの終了や閲覧データの削除でも保存内容が失われ得ます。作品のバックアップとしては扱いません。

**画面に入力して保存した内容は、Monacaの公開URLには含まれません。** 公開URLで相手へ渡るのはソースです。提出先にも見せるアレンジは、`createInitialItems()`内の初期データ、HTMLの文章、CSSの色などを変更します。変更後は自分の検証用保存内容を初期化し、ソースに書いた初期状態が見えることを確かめます。実際の提出では新しい取り込み先でも確認します。
