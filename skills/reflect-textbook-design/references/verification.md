# 検証の選び方

## 検証する範囲

変更した規則ごとに、確認する箇所と期待値を先に決める。共有CSSの変更で全単元の全画面を操作することは既定にしない。全対象ページへの適用範囲の調査と、代表ページの実表示確認を区別して記録する。

| 変更 | 必要な確認 |
| --- | --- |
| 色だけ | M01の該当用途と、同じ色が別用途へ誤って波及していないこと。リンク・構文色・確認欄などの状態差を選ぶ |
| フォント・太さ・行高 | M01の表紙、本文の長い段落、表、コード、日本語を含むコード、ファイル名。適用規則が異なる言語・共通資料・教員用ガイドも代表確認 |
| 余白・幅・配置 | M01の変更箇所と、長い見出し・広い表など影響が出る別単元。1440pxとPC画面分割幅で確認 |
| 操作部分の見た目 | 変更した目次・折りたたみ・チェック欄などの開閉・選択・フォーカス状態。既存の操作が保たれること |
| 共通フォントや全体寸法 | 上記に加えて印刷の代表ページと、展開した配布ZIPのオフライン表示 |

F01/F02の差分ブロックは、追加・削除・既存行・省略行を区別でき、コード内容を変えていないことを確認する。アラビア語では本文のRTL・コードのLTR・目次の開閉位置・共通資料からの戻り先を確認する。

M01にない部品は、`config/teaching-materials.json` とHTMLの検索から実在する代表箇所を選ぶ。単元名やファイル数を固定しない。共通資料・教員用ガイドを確認するのは変更の影響を確かめるためであり、M01のレイアウトに作り直すためではない。

## 必須のリポジトリ検査

新規の配布ファイルをパス指定でstageし、`AGENTS.md` の手順で次を通す。

```sh
python3 scripts/check-teaching-materials.py
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/localize-student-materials.py check
python3 scripts/package-student-materials.py
```

Python 3.11以上を使う。`AGENTS.md` §7に従い、Flutterの静的解析も実施する。Monaca・Flutterの完成コードや実機の表示を変えないデザイン反映では、クラウドIDEやエミュレータの画面確認を追加しない。アプリ側も対象となった場合のビルド・操作確認は同節に従う。

## ブラウザでの比較条件

- 作業用プロファイルを付けたheadless Chromeを使う。オーナーのブラウザやクリップボードは操作しない。
- 基準はFigmaフレームと同じ幅。現在のM01は1440 CSS px、ズーム100%。OS、Chromeのバージョン、DPR、言語、開閉状態、スクロール位置を記録する。
- PCで画面分割した幅も確認する。既定の検証例は720 CSS px。変更した規則のブレークポイント付近に疑いがある場合だけ追加する。
- `document.fonts.ready` を待ち、対象画像の読込・decodeとレイアウトの安定を確認してから撮影する。
- `getComputedStyle` で対象の色、太さ、サイズ、行高、余白を確認する。相対値や計算式は、その条件で解決した値を比べる。
- `font-family` の計算値だけでは、実際に使われた書体を証明できない。フォントの読込結果に加え、利用可能ならChrome DevTools Protocolの `CSS.getPlatformFontsForNode` 等で代表文字の実フォントを確認する。本文・コード・コード内日本語・変更した言語を区別する。
- Figmaと同じ文言・幅・フォント条件で改行が異なる場合は、幅、padding、太さ、字間、行高、欠けた文字のフォールバックを先に調べる。原因未確認のまま描画誤差としない。

Figmaへの追加インポートや比較用フレーム作成は通常不要。スクリーンショットの画像差分は原因調査の補助とする。同じ環境内の変更前後比較には使えるが、FigmaとChromeの全画素一致や、全要素一律の「±1px」を合格条件にしない。

## 受け入れる差・解消する不具合

| 判定 | 例 |
| --- | --- |
| 設計値を合わせる | 色、不透明度、書体、太さ、文字サイズ、行高、字間、コンテンツ幅、余白、角丸、枠線 |
| 原因を説明したうえで許容 | 同じ設計値を指定した後のアンチエイリアスなどの描画差。別言語・別本文量・別幅に応じた正常な折り返しとページ高の違い |
| 解消する | 想定外のフォント、太さの誤解決、文字切れ、重なり、本文の欠落、ページ全体の横はみ出し、読めない配色、操作不能、印刷時の内容欠け |

配色が読めないなどFigmaの指定自体に問題がある場合は、影響箇所と根拠をLeo Andoへ提示する。コードだけで別の配色を採用せず、デザインの決定後にFigmaとコードをそろえる。

## ZIP・印刷・言語

生成したZIPの収録ファイルと、展開後の相対パスを確認する。フォント変更時はフォント本体・ライセンスの収録を確かめ、ネットワークを切った状態で代表HTMLを開く。ローカルのキャッシュにあるWebフォントに依存した検証にしない。

言語別指定を残した場合も、共有書体の変更が翻訳内の日本語やコードへ届くことがある。変更した規則が当たる代表言語を選び、理由を記録する。印刷では画面用寸法をそのまま強制せず、既存の印刷規則で本文・表・コードが欠けないことを確かめる。

## 記録と打ち切り

結果は `AGENTS.md` の検証表で「確認済み／一部確認／未確認」を区別する。対象コミット、確認したページ・状態・幅、期待値と結果、未確認の理由、次の最小操作を残す。比較画像や取得データは指定のリポジトリ外フォルダへ置く。

環境準備は `AGENTS.md` の上限に従い、環境を変えない同じ再試行を繰り返さない。コードを読んだだけの項目を実表示確認としない。確認できなかったことを、デザインや教材自体の不具合と断定しない。

## 精度方針の背景

精度方針の正本は、このリポジトリの `README.md`「教科書のデザインをFigmaから反映する（教員用）」とする。設計値に含まれる意図した小数を保持し、表現誤差と確認できる値だけを整理する。

CSSの数値は小数を含み、CSS pxと物理ピクセルは区別される。また、使用値と実際の描画値は環境によって異なり得る。これを踏まえて、本スキルでは設計値の照合と実表示の確認を併用する。

- [W3C CSS Values: Numbers](https://www.w3.org/TR/css-values-4/#numbers)
- [W3C CSS Values: Absolute lengths](https://www.w3.org/TR/css-values-4/#absolute-lengths)
- [W3C CSS Cascade: Actual values](https://www.w3.org/TR/css-cascade-4/#actual)
