困ったとき

コードが赤くなった、画面が出ない、動作しない、原因が分からない。
エラーに向き合い、自分で解決するための調べ方をまとめています。

  1. 1. エラーが起きたときの調べ方
  2. 2. 開発環境別の確認ポイント
  3. 3. どうしても解決しないときは（完成プロジェクトの確認）

1. エラーが起きたときの調べ方

プログラミングでエラーが出るのは自然なことです。エラーメッセージには「どのファイルの何行目で、何が問題か」が書かれています。焦らずに上から順に確認しましょう。

  1. 各単元の「困ったとき」表を確認する
    教科書の末尾にある「困ったとき」には、その単元でよくある状態と確認場所がまとまっています。
  2. 最初の赤い行を見る
    エラーが複数出ているときは、一番上の「最初の赤い行」を直します。最初の1つを直すと、あとのエラーがまとめて消えることがよくあります。
  3. 直前のSTEPと見比べる
    手順を1つ飛ばしていないか、大文字・小文字やスペル（綴り）、全角スペースが混ざっていないかを確認します。
  4. 先生に質問するときは
    「STEP番号・編集したファイル・最初の赤い行・実行した操作」を伝えると、原因が早く分かります。

2. 開発環境別の確認ポイント

開発環境確認するポイント参考資料
Monaca クラウド IDEプレビュー画面下の「デバッグログ」やブラウザの開発者ツール（F12/右クリック→検証）のConsoleタブを確認します。JavaScriptの構文エラーやファイル読み込みエラーが赤く表示されます。共通：準備（Monaca）
Flutter / Visual Studio Codeターミナル（Terminal）のエラー出力や、エディタ下部の「PROBLEMS（問題）」タブを確認します。flutter pub get の実行漏れやパッケージの指定誤りを確認します。共通：準備（Flutter）

3. どうしても解決しないときは（完成プロジェクトの確認）

どうしても自分のコードの間違いが見つからないときや、アプリ本来の動きを確認したいときは、先生が用意した完成プロジェクト（見本）を開いて自分のコードと見比べることができます。

完成プロジェクトは「答え合わせ用」です

完成プロジェクトからコードをそのままコピーしたり、完成プロジェクトを改造して提出しても、自分の課題の提出にはなりません。見本で違いを確認したら、必ず自分で作ったプロジェクトに戻り、自分の手で修正してください。

見本の場所と開き方

  1. Finderで 書類（~/Documents）にある配布フォルダ（hybrid-app-student-materials-日付）を開きます。
  2. その中にある samples フォルダから、該当する単元のフォルダ（例：M01OshiList、F01StampBoard など）を確認します。
  3. Monaca単元（M01・M02）：samples の中にあるHTML/CSS/JSファイルをテキストエディタで開き、自分のコードと見比べます。Monaca クラウド IDE上で見本を動かして確かめたいときは、先生がZIPにして公開した取り込み用URL（M01OshiList / M02OshiSave）を通常版Monacaへログインした状態で開いて取り込みます。取り込むとFreeプランの枠を1枠使います。Freeプランの制限で取り込めない場合でも、samples のコードを直接読めば進められます。
  4. Flutter単元（F01・F02）：Visual Studio Code の File → Open Folder… で該当フォルダを選んで開きます。見本でコードや動作を確認したら、自分の制作フォルダ（~/Documents/HybridApp）を開き直して作業を続けます。

取り違えに注意

見本と自分のアプリは同じプロジェクト名です。ウィンドウ上部やタブに表示されるフォルダパスを確認し、見本のほうを編集してしまわないよう注意しましょう。
