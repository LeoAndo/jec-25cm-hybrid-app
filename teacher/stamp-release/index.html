F02StampRelease：入力・保存・APK提出

入力した習慣を保存し、再起動で復元する仕組みを作ります。保存の完了と画面更新の順序を確かめ、実際に提出するAPKをインストールして確認します。

この単元の教材方針

新概念はFuture・async / awaitによる非同期処理の1つです。Futureの結果、await後の続き、待機中の画面、成功と失敗を1つの処理の流れとして教えます。Java／Swiftの非同期APIを履修済みとは仮定せず、同期的な順次処理との比較から始めます。

入力はコマ12の同期処理で先に完成させ、コマ13で保存完了を待つ形へ変更します。毎コマの開始コード、新規作成・配置・実行手順は本単元へ再掲し、前の教科書へ送りません。学生は自分の既存のスタンプ帳を続けてよく、配布見本のF02という名前に合わせてコピーを増やす必要はありません。

保存形式は名前・理由・回数の3つ組を並べたList<String>です。MonacaやJSONをFlutterの前提にしません。大規模な構造・移行・検索を扱うデータベースではなく、固定した小さな記録の例です。パッケージは重要なデータの永続性を保証する用途には使わず、必要な記録を別に控えるよう説明します。

APK提出と採点

提出先・締め切り・指定ファイル名は教員が授業中に案内します。提出先の容量上限は100MB以上またはなしと確認済みなので、flutter build apkの通常APKを使います。実測の完成見本は48,666,844 bytes（約48.7MB）です。学生が素材を変えた場合も容量を確認します。

提出対象はapp-release.apkの確認済みの写しで、debug APKやプロジェクトZIPではありません。生成テンプレートのdebug鍵を使い、署名鍵の作成やストア公開は扱いません。教員は別の検証端末で初期アレンジ、空欄、追加、保存、再起動、詳細、0と上限を確認します。入力済みの記録はAPKに入らないため、createInitialHabitsなどソースに残るアレンジを評価します。

同じapplicationIdの学生作品は上書きインストールで既存データが残る場合があります。教員の採点専用端末で、前の採点用コピーと必要な記録を整理したうえで新規状態を確認します。学生の制作端末や本人の必要なデータを一律に消させません。

  • STEP 16：本文は、目標回数を小さくしてRで読み込み直したときの読込エラーだけを書いています。stampGoalを小さくしてrで反映すると、読込の検査は行われず、「3 / 2 回 · あと-1回」と出て、スタンプを押すは無効、1つ戻すで上限の回数へ戻せます。F01では #41 で本文に足した見え方と同じ種類です（F02では1つ戻すが効く点がF01と違います）。確かめ直すと、1つ戻すが効くのは、回数が新しい目標を1回だけ超えているときでした。5回のまま目標を3にしてrすると「5 / 3 回 · あと-2回」と出て、1つ戻すを押しても変わりません。F01と同じく、changeStampが目標を超える次の回数を受け付けないためで、F01の #41 の例（5回で目標3）との違いは、超えた回数の違いでした。2026-09-25、STEP 16の本文に、rで反映したときの見え方と、1つ戻すが効く場合と効かない場合、目標を超えた回数が残ったままRを押すと読込エラーになり、初期化で戻すことを書き足しました。「困ったとき」と、このガイドのつまずき表にも1行ずつ加えています（コードは変えていません。issue #80）。
  • STEP 10〜12（issue #80で、あわせて見直した点）：Androidのアプリ情報とアイコンに出る名前は、MaterialAppのtitleの「スタンプ帳」ではなく、プロジェクト名のf02_stamp_releaseです（F01から続ける学生はf01_stamp_board）。2026-09-25、STEP 12の手順4にこの名前を書き足しました。初回のAndroidビルドのログに出る「Warning: SDK processing. This version only understands SDK XML versions up to 3…」（ビルドは成功）は、つまずき表に1行加えました。STEP 06の抜粋と配布見本のpubspec.yamlでは、shared_preferencesとflutterの並びが違いますが、pub get後のpubspec.lockは同じなので直していません（issue #80）。

Visual Studio Codeからの操作（Flutter: Launch Emulatorでの起動と選択、ホットリロード）、Android StudioのDevice Manager、Finderでの容量と更新日時の表示、キーボードの日本語変換での入力、指定された提出先への提出と取り直し、iOS 26.5以外のシミュレータ、学生全員のSDK・端末の組み合わせ、教室の初回同時取得時間は未確認です。スクリーンショットは掲載していません。
